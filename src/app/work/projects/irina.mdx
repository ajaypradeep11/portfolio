## Overview

IRINA is an apparel engineering workspace for moving from a garment idea to production geometry. A user can begin with a reference image or open a blank technical-flat canvas, assemble a garment from parametric foundations and construction components, adjust measurements and fit, validate the result, and export files for pattern review and cutter preparation. The product is being built as a single monolith with a Next.js frontend and a NestJS API so the interactive editor and the deterministic geometry engine can evolve together behind clear contracts.

The central design decision is that an uploaded image is **evidence, not production geometry**. Image understanding can propose a silhouette, landmarks, and construction components, but it should never send guessed pixels directly to a cutting machine. IRINA rebuilds the result from normalized measurements, formula-driven components, seam relationships, notches, grainlines, and manufacturing rules. The current implementation therefore focuses on the trustworthy part of the pipeline: validated image intake, editable parametric flats, deterministic shirt and pocket drafting, physical-size SVG/PDF output, layered DXF, and a guarded Gerber handoff.

## Key Features

- **Two creation flows**: Start from a garment reference through a guided image-upload experience, or begin from an empty manual canvas and add a complete shirt foundation or standalone construction components.
- **Parametric technical-flat editor**: Front and back shirt views are assembled from editable scene layers for panels, collars, yokes, sleeves, cuffs, plackets, buttons, pockets, measurement guides, and construction skeletons.
- **PCCE component model**: Components such as patch pockets keep a stable identity, revision, parameters, placement, validation state, and pattern output. Changing width, height, radius, pleat, flap, stitch style, or position immediately updates the flat and downstream manufacturing data.
- **Measurement-driven shirt foundations**: Classic, workwear, and overshirt blocks respond to chest, waist, body length, shoulder width, and fit allowances while reconciling linked construction relationships such as collar-to-neckline, sleeve-cap-to-armscye, cuff-to-sleeve, and yoke-to-back.
- **Deterministic pattern drafting**: The NestJS service generates millimetre-based `PatternSet` documents containing semantic pieces, cut quantities, internal lines, notches, grainlines, seam allowances, and validation results without relying on AI inference.
- **Production exports**: Patterns can be delivered as physical-size SVG, calibrated plotter PDF, layered Standard DXF with CUT/NOTCH/DRILL layers, a named Gerber C200/CutWorks G71 legacy profile, or an `IRINA-CUT/1.0` diagnostic plan.
- **Safety-first cutter handoff**: The UI explains that DXF must be imported into CutWorks, mapped to the installed tools, scanned for errors, simulated, and converted for the exact controller. Legacy NC output explicitly discloses omitted notch operations and quantity limitations instead of presenting itself as universal machine code.
- **Validated image references**: JPG, PNG, and WebP uploads are checked by actual binary signatures, dimensions, and size limits before being stored through a cloud-neutral persistence interface.

## Technologies Used

- **Next.js 16 + React 19 + TypeScript**: The frontend provides the project dashboard, upload workflow, AI-studio concept, flat-sketch editor, component library, inspectors, pattern preview, and export flows. The UI uses native React state and SVG geometry so technical drawings remain sharp and directly interactive.
- **NestJS 11 + TypeScript**: A modular REST API owns image-reference intake, PCCE component commands, shirt-document evaluation, pattern drafting, validation, and export endpoints.
- **Parametric geometry engine**: Formula evaluation, component definitions, domain commands, validators, and event buses keep construction data separate from rendering. The same design document can drive the screen preview, pattern pieces, measurements, grading consumers, marker logic, and exports.
- **SVG + PDFKit**: Technical flats and pattern pieces are represented as vector geometry. SVG supports browser preview and physical-size downloads, while PDFKit creates custom plotter pages with a 100 mm calibration square.
- **DXF and Gerber-oriented export services**: The backend emits broadly importable Standard DXF layers for CutWorks and a carefully scoped G71 legacy NC candidate based on documented C200/CutWorks semantics.
- **Jest + Supertest**: Unit and end-to-end suites cover formula evaluation, component commands, image inspection and storage, shirt and pocket drafting, API behavior, SVG/PDF/DXF generation, CNC plans, and Gerber profile rules.

## Challenges and Learnings

The hardest problem is preserving a trustworthy boundary between generative interpretation and manufacturing output. Fashion images are ambiguous: perspective, fabric drape, lighting, and styling can all hide the real construction. Treating an AI result as cutter-ready would be unsafe. IRINA instead uses image analysis to suggest structured components and then passes control to a deterministic document model whose measurements, formulas, seam relationships, and validation rules are inspectable. This architecture makes AI useful without letting it become the source of truth for physical production.

The editor introduced a second challenge: one change must stay coherent across many representations. Moving or resizing a pocket affects the flat sketch, its panel containment validation, the component revision, pattern geometry, fabric estimates, and eventually marker and export consumers. I handled this by giving components stable identities and explicit commands, then publishing domain events to subscribed consumers rather than coupling every UI surface directly to every other one.

Machine export required equal restraint. “Gerber compatible” is not one universal file format, and cutter behavior depends on the controller, firmware, installed tools, and material configuration. The safest verified workflow is layered DXF into CutWorks, followed by operator mapping and simulation. The legacy G71 generator is deliberately named for the profile it targets and surfaces what it cannot yet represent. The lesson was that production software earns trust by making limitations visible, not by hiding them behind a download button.

## Outcome

IRINA is an active development project with the core engineering loop working: create a garment document, edit parametric construction, validate geometry, draft semantic pattern pieces, and prepare vector or cutter-oriented output. The product already demonstrates both image-led and manual workflows, a reusable component architecture, physical-unit pattern generation, and a researched CutWorks handoff. The next phase is to connect a production image-understanding model to the existing reference pipeline while keeping deterministic geometry and operator-reviewed export as the final authority.
